## 1. Purpose

This document defines how **Royalty OS v0.4** can align with national, international, and cross-border AI infrastructure.

Royalty OS v0.4 is not a national AI infrastructure.
It is not a government program, legal framework, diplomatic treaty, or enforcement mechanism.

Instead, Royalty OS v0.4 provides a **value relationship governance layer** that can support AI infrastructures where data, models, agents, institutions, creators, researchers, and societies interact across multiple layers.

The purpose of this document is to clarify how Royalty OS v0.4 may support:

* national AI infrastructure,
* cross-border AI collaboration,
* scientific AI platforms,
* value traceability,
* reviewable attribution,
* policy-guided governance,
* auditability,
* and responsible value relationship evolution.

The central alignment statement is:

```text
National AI infrastructure provides the vessel.
Royalty OS v0.4 provides a governance structure for value relationships flowing through that vessel.
```

---

## 2. Background

Recent national AI infrastructure initiatives indicate a shift from isolated AI tools toward integrated AI platforms.

These platforms may combine:

* large-scale datasets,
* high-performance computing,
* AI foundation models,
* AI agents,
* research automation,
* public-private collaboration,
* scientific workflows,
* institutional governance,
* and cross-border cooperation.

This shift creates a new structural requirement.

When AI systems operate across national, institutional, and organizational boundaries, value relationships become more complex.

Questions arise:

```text
Who contributed what?
Which dataset influenced which output?
Which prompt, model, document, or workflow created value?
Which human or institution should be acknowledged?
Which relationship requires review?
Which action is governance, and which action would become execution?
Which policies apply across jurisdictions?
```

Royalty OS v0.4 addresses these questions at the structural level.

It does not automatically decide value.
It does not execute compensation.
It does not replace law, diplomacy, institutional review, or human judgment.

It provides a structured way to represent, review, govern, and evolve value relationships.

## 3. Positioning

Royalty OS v0.4 should be understood as a **Dynamic Value Relationship OS**.

Its role is not to control AI infrastructure itself.

Its role is to structure the relationships that emerge when AI infrastructure uses, transforms, references, derives, or circulates value.

```text
AI infrastructure layer:
  data
  compute
  models
  agents
  workflows
  institutions

Royalty OS v0.4 layer:
  value records
  value events
  value graphs
  policy modules
  governance actions
  OS event logs
  review boundaries
```

In this sense, Royalty OS v0.4 can sit:

```text
above national AI infrastructure,
beside institutional governance systems,
between cross-border collaboration layers,
and within AI-assisted value review workflows.
```

## 5. Multi-Layer Value Graph as Cross-Border Value Mapping

Cross-border AI infrastructure cannot rely on a flat model of value.

A single AI-generated output may involve:

* a human idea,
* a source document,
* a dataset,
* a prompt,
* a model,
* an agent workflow,
* a scientific institution,
* a review process,
* a policy module,
* and a governance action.

Royalty OS v0.4 addresses this through the **Multi-Layer Value Graph**.

The graph separates different kinds of value relationships into layers:

```text
1. Contribution Layer
2. Reference Layer
3. Derivation Layer
4. Review Layer
5. Policy Layer
6. Governance Layer
7. Event Layer
```

This layered structure allows international systems to avoid collapsing all relationships into a single attribution claim.

For example:

```text
Contribution is not the same as reference.
Reference is not the same as derivation.
Derivation is not the same as ownership.
Policy guidance is not the same as legal judgment.
Governance action is not the same as automatic execution.
```

This distinction is essential for international alignment.

Without such separation, AI infrastructure risks confusing:

```text
trace with ownership,
score with judgment,
review with enforcement,
policy with law,
and governance with automatic execution.
```

Royalty OS v0.4 prevents this collapse by separating structural layers.

## 6. Policy Modules as Jurisdiction-Aware Governance Units

National and cross-border AI infrastructures operate under different legal, cultural, institutional, and ethical conditions.

Therefore, a single universal policy is not sufficient.

Royalty OS v0.4 introduces **Policy Modules** as separable governance units.

Policy Modules may represent:

```text
Attribution Policy
Contribution Policy
Review Policy
Dispute Policy
Redistribution Policy
Archival Policy
Migration Policy
Jurisdiction-Specific Policy
Institution-Specific Policy
Community-Specific Policy
```

This allows Royalty OS v0.4 to support international alignment without forcing one universal rule onto all contexts.

A Policy Module may guide:

* how attribution should be reviewed,
* what evidence is required,
* when human review is necessary,
* when a dispute should be escalated,
* when a relationship should be archived,
* how old records migrate into new graph versions,
* and what actions are prohibited.

However:

```text
Policy Module != final judge
Policy Module != legal authority
Policy Module != automatic enforcement engine
```

A Policy Module guides review.
It does not replace review.

## 7. Dual Boundary Model for Safe International Use

International AI infrastructure requires strong boundaries.

Royalty OS v0.4 defines two major boundaries:

```text
1. Scoring Boundary
2. Execution Boundary
```

### 7.1 Scoring Boundary

The Scoring Boundary prevents review signals from becoming final value judgments.

Examples of signals include:

```text
trace strength
contribution confidence
reference density
derivation proximity
review priority
```

These signals may assist review.

They must not automatically become:

```text
final attribution
legal ownership
compensation amount
institutional liability
or reputational judgment
```

### 7.2 Execution Boundary

The Execution Boundary prevents governance recommendations from becoming automatic enforcement.

A governance action may recommend:

```text
acknowledge
flag
defer
merge
split
revise
escalate
reject
archive
```

But it must not automatically trigger:

```text
payment
legal claim
punishment
public accusation
final ownership assignment
or irreversible enforcement
```

This boundary is especially important for international systems where legal and cultural contexts differ.

## 8. OS Event Log as Audit and Traceability Layer

National AI infrastructure requires auditability.

Royalty OS v0.4 introduces the **OS Event Log** to record system-level changes.

An OS Event may record:

```text
value relationship created
value relationship updated
policy module applied
governance action recorded
review state changed
graph layer added
graph migration performed
compatibility mapping created
```

The OS Event Log is not intended to become a surveillance mechanism.

Its purpose is structural accountability.

```text
OS Event Log = accountability layer
OS Event Log != surveillance layer
```

This distinction is critical.

The OS Event Log should record meaningful structural changes, not excessive personal behavior.

## 9. International Extension Points

Royalty OS v0.4 can be extended for international protocol alignment through the following extension points.

### 9.1 Jurisdiction Metadata

Future schemas may include jurisdiction-related metadata.

Example:

```text
jurisdiction:
  country
  region
  institution
  applicable_policy_modules
  review_requirements
```

This allows policy modules to adapt to different institutional or national contexts.

### 9.2 Cross-Border Value Relationship IDs

International infrastructure may require stable identifiers for cross-border value relationships.

Example:

```text
cross_border_relationship_id
origin_jurisdiction
target_jurisdiction
participating_institutions
review_authority
```

### 9.3 Institution-Level Policy Modules

Different institutions may define their own policy modules.

Example:

```text
university_policy_module
national_lab_policy_module
publisher_policy_module
repository_policy_module
research_consortium_policy_module
```

### 9.4 International OS Event Types

Future OS Event schemas may include event types such as:

```text
cross_border_policy_applied
jurisdiction_mapping_created
institutional_review_requested
international_dispute_flagged
cross_border_graph_migration_completed
```

### 9.5 Public Accountability Layer

National AI infrastructure may need public-facing summaries.

Royalty OS should distinguish between:

```text
internal audit logs
public transparency summaries
private review records
restricted governance records
```

This protects privacy while supporting accountability.
